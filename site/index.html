      This page boots a Linux-style bzImage in v86, an x86 emulator compiled to WebAssembly, and lets you look inside the machine while it runs. Two kernels come with it: hello, a toy kernel that prints two lines and halts, and minified-linux, the reduced Linux kernel of minimal-kernel-build. Any bzImage can be loaded from disk.
      
  
      Tabs
      
  
        
    
      • Memory: the physical memory map from the boot header and one square per 4 KiB page, coloured by region and ELF section.
        • 
    
      • Page: one page as a single listing, instructions where the kernel has code and hex rows elsewhere, with symbol headers.
        • 
    
      • Debugger: registers, stepping and run-to-address.
        • 
    
      • Graph: the symbols the CPU went through while stepping and the transitions between them, live.
        • 
    
      • Snapshots: save, restore and download the whole machine state.
        • 
  
      
  
      Counting and stepping
      
  
      v86 normally runs guest code through a JIT, at least 100,003 instructions per call, and has no single-step API. The page adds two exports to v86's own v86.wasm at load time (the functions are already in it and named in its name section, the code is unchanged): read_imm8, which fetches the byte at EIP, and the interpreter's run, which executes one instruction. Stepping calls them from JavaScript the way v86's interpreter loop does. By default every boot steps BIOS and setup as fast as possible to the kernel entry at 0x100000, then the kernel runs at 1k instructions per second, counted live, until "Hello, World!" and "Still alive" are both in VGA text memory at 0xb8000 (hello: about 6 s; the minified Linux: about 15 minutes, with an ETA). With speed set to full (remembered, or ?speed=full) and count on, the whole boot is stepped in the background first and then runs on v86's JIT.
      
  
      The counts are exact for the run shown, with two caveats: a rep string instruction counts once per v86 entry, and v86 runs at most a page of iterations per entry; SeaBIOS waits on real time, so the part before the kernel varies between runs; and the minified Linux's calibrate_delay() loops until a timer tick, so its count from 1 MiB depends on how fast the page steps. hello's kernel count is the same every run and matches qemu instruction for instruction. site/README.md has the cross-check against qemu.
